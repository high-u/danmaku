# danmaku スキル

## CRITICAL: スキル起動直後にやること

このスキルが起動したら、SKILL.md を読み終えただけで応答を返してはならない。次の順で **実際に bash を呼んでコマンドを実行する**:

1. すぐ下の「前提チェック」のコマンドを bash で実行する
2. 3 つすべて合格したら、後述の「1 ターンの手順」の手順 1 (`getscreens`) を bash で実行する
3. 利用者が指定した継続時間または回数の間、手順 1 から 6 までを bash 実行で繰り返す

「I will start the danmaku process」「the skill handles the loop internally」のような宣言で停止することは禁止。各ターンで getscreens / 画像読込 / danmaku-cli / sleep を必ず**自分で**実行する。

## 前提チェック（ループ開始前に 1 回だけ）

次のコマンドを実行して 3 つ全てが見つかることを確認する。

```
which getscreens
which danmaku-cli
pgrep -f danmaku-gui-linux
```

いずれかが見つからない（非ゼロ終了）場合は、利用者に「`getscreens` / `danmaku-cli` のビルドと `danmaku-gui-linux` の起動が必要です」と伝えてループを開始しない。ビルド手順・起動手順はこのスキルの範囲外。

## 利用者指示の解釈

利用者の自然言語指示から次の 3 つを読み取る。

- **継続時間または回数**: 「10 分間」「30 回」「止めるまで」など
- **観察の観点**: 「コードレビュー視点で」「励まして」「ツッコミ多めで」など。指定がなければ後述の既定方針
- **間隔**: 「30 秒ごとに」「ゆっくりめで」など。指定がなければ 15 秒

例:
- 「今から 10 分間、スクショを見て弾幕を流して」→ 10 分間ループ、観点は既定、間隔は 15 秒
- 「コードを書いてる間ツッコミを 5 秒ごとに入れて」→ 利用者が止めるまで、観点はツッコミ寄り、間隔は 5 秒

## 1 ターンの手順（各ステップを bash で実際に実行する。順番厳守）

1. **スクリーンショット取得**

   ```
   getscreens
   ```

   stdout に JSON 配列が 1 行出力される。例:

   ```json
   [{"screen":0,"path":"/run/user/1000/getscreens/0/20260516-120000.png","timestamp":"20260516-120000"}]
   ```

   非ゼロ終了した場合は stderr の内容を利用者に提示してループを停止する。

2. **画像を読み込む**

   JSON 配列の最初の要素の `path` を取り出し、エージェント標準の画像読み込み機能でその PNG ファイルを読む。

3. **コメントを生成する**

   「コメントの作り方」の節に従って 1〜5 本の短いコメント文字列を作る。

4. **弾幕を送信する**

   生成したコメントを位置引数として `danmaku-cli` に渡す。

   ```
   danmaku-cli "コメント1" "コメント2" "コメント3"
   ```

   非ゼロ終了した場合は stderr の内容を利用者に提示してループを停止する（socket 不通や GUI 未起動の可能性が高く、続行しても無駄なため）。

5. **待機する**

   ```
   sleep 15
   ```

   秒数は利用者指示で上書きする。`sleep` 以外の手段（Python スクリプト等）を使う必要はない。

6. **終了条件を判定する**

   - 継続時間指定の場合: ループ開始時刻からの経過時間が指定時間を超えたら終了
   - 回数指定の場合: 実行ターン数が指定回数に達したら終了
   - 「止めるまで」指定の場合: 利用者が中断するまでループ。エージェント側からは終了しない

   終了しない場合は手順 1 に戻る。

## コメントの作り方

- **キャラクター**: ニコニコ動画のコメント欄の文体。短い口語、やじ、ツッコミ、感想、共感。「www」「それな」「乙」「がんばれ」のような語彙も可
- **長さ**: 1 本あたり全角 30 文字以内目安。長文は避ける
- **本数**: 1 ターンで 1〜5 本。画面が静かなターンは 1〜2 本、にぎやかなターンは多め
- **前ターンとの差分があれば触れる**: 直前ターンのスクショがまだ会話コンテキストに残っている場合は、前ターンから明らかな変化（新しいエラー、コードの進展、ウィンドウ切り替え等）があるか見て、変化があればそこに触れるコメントを優先する。前ターンの画像が残っていない、または変化が見当たらなければ画面の今の様子にコメントする
- **避けるもの**:
  - パスワード・メールアドレス・電話番号・クレジットカード番号など、画面に偶然映った機密情報をそのまま読み上げない
  - 同じコメントの連投。前 2〜3 ターンと似た内容は避ける
  - 利用者個人への攻撃的な内容
- **観点が指定されたとき**: 利用者の指示（例: 「コードレビュー視点」「励まして」）を最優先する。キャラクターより観点を優先

例（コードを書いている画面の場合）:

```
danmaku-cli "またネストしてんのかよｗ" "そろそろ関数に切り出せ" "がんばれ"
```

例（ブラウザでドキュメントを読んでいる画面の場合）:

```
danmaku-cli "勉強熱心" "それ前も読んでなかった？"
```

## エラー時の挙動まとめ

| 状況 | 対応 |
|---|---|
| 前提チェック失敗 | ループを開始しない |
| `getscreens` が非ゼロ終了 | stderr を利用者に提示してループを停止 |
| 画像読み込みに失敗 | エラー内容を利用者に提示してループを停止 |
| `danmaku-cli` が非ゼロ終了 | stderr を利用者に提示してループを停止 |

いずれも回復する可能性が低いため、リトライや次ターンへの継続はしない。
