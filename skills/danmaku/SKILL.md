# danmaku スキル

利用者の作業画面を観察し、画面内容に応じたコメントをニコ動風の弾幕として流す。スキル起動後、下記の前提チェックを 1 回行い、続けて「1 ターンの手順」を指定ターン数だけ繰り返す。

## 用語

- **ターン数**: ループの周回数。1 ターン = 「1 ターンの手順」を 1 周まわすこと
- **コメント数**: 1 ターンの中で `danmaku-cli` に渡すコメント文字列の個数（1〜5 個）

利用者が「N 回」と言ったときは **ターン数 N** を指す。

## 前提チェック（ループ開始前に 1 回だけ）

次のコマンドを bash で実行する。

```
which getscreens
which danmaku-cli
pgrep -f danmaku-gui-linux
```

3 つすべてが見つかれば（全て 0 終了）ループを開始する。1 つでも失敗したら、利用者に「`getscreens` / `danmaku-cli` のビルドと `danmaku-gui-linux` の起動が必要です」と伝えて終了する。

## 利用者指示の解釈

利用者の自然言語指示から次の 3 つを読み取る。

- **ターン数または継続時間**: 「3 回」「10 分間」「止めるまで」など
- **観察の観点**: 「コードレビュー視点で」「励まして」「ツッコミ多めで」など。指定がなければ既定（やじ・ツッコミ・感想）
- **間隔**: 「30 秒ごとに」「ゆっくりめで」など。指定がなければ 15 秒

## 1 ターンの手順

次の 4 ステップを bash で順番に実行する。これで 1 ターン消化。

### 1. スクリーンショットを撮ってパスを取得

```
getscreens
```

stdout に JSON 配列が 1 行出力される。例:

```json
[{"screen":0,"path":"/run/user/1000/getscreens/0/20260516-120000.png","timestamp":"20260516-120000"}]
```

配列の最初の要素の `path` を取り出して次のステップに渡す。

### 2. スクリーンショットを読み込む

ステップ 1 で取得した PNG パスを、エージェント標準の画像読み込み機能で読む。前ターンの画像はコンテキストに残っていることがあるが、`sleep` の間に画面内容は変わるので、ターン毎に新しい画像を読み込む。

### 3. コメントを danmaku-cli で送出

「コメントの作り方」に従って 1〜5 個の短いコメントを作り、位置引数として渡す。

```
danmaku-cli "コメント1" "コメント2" "コメント3"
```

成功時は `sent N message(s) to screen 0` が stdout に出る。

### 4. 待機

```
sleep 15
```

秒数は利用者指示で上書きする。

## ターン数分繰り返す

ステップ 1〜4 を 1 ターンとして、利用者指示のターン数だけ繰り返す。各ターンの開始時に、現在が何ターン目で残り何ターンかを 1 行で書き出してから手順 1 に入る。例:

```
ターン 2/3 開始
```

継続時間指定の場合は、最初のターンの開始時刻を記録しておき、毎ターン手順 4 の sleep 後に経過時間で判定する。「止めるまで」指定の場合は利用者が中断するまでループする。

## コメントの作り方

- **キャラクター**: ニコニコ動画のコメント欄の文体。短い口語、やじ、ツッコミ、感想、共感。「www」「それな」「乙」「がんばれ」のような語彙も可
- **長さ**: 1 個あたり全角 30 文字以内目安
- **コメント数**: 1 ターンで 1〜5 個。画面が静かなターンは 1〜2 個、にぎやかなターンは多め
- **前ターンとの差分があれば触れる**: 直前ターンのスクショがまだ会話コンテキストに残っている場合は、変化（新しいエラー、コードの進展、ウィンドウ切り替え等）があるか見て、変化があればそこに触れるコメントを優先する。残っていないか変化が見当たらなければ画面の今の様子にコメントする
- **観点が指定されたとき**: 利用者の指示（例: 「コードレビュー視点」「励まして」）を最優先する。キャラクターより観点を優先
- **機密情報の保護**: パスワード・メールアドレス・電話番号・クレジットカード番号など、画面に偶然映った機密情報はコメントに含めない

例（コードを書いている画面）:

```
danmaku-cli "またネストしてんのかよｗ" "そろそろ関数に切り出せ" "がんばれ"
```

例（ブラウザでドキュメントを読んでいる画面）:

```
danmaku-cli "勉強熱心" "それ前も読んでなかった？"
```

## エラー時の挙動

| 状況 | 対応 |
|---|---|
| 前提チェック失敗 | ループを開始しない |
| `getscreens` が非ゼロ終了 | stderr を利用者に提示してループを停止 |
| 画像読み込みに失敗 | エラー内容を利用者に提示してループを停止 |
| `danmaku-cli` が非ゼロ終了 | stderr を利用者に提示してループを停止 |

いずれも回復可能性が低いため、リトライや次ターンへの継続はしない。
